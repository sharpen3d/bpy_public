OpenVAT

OpenVAT started as a way to bake Blender animation into textures. It’s also a Unity system for bringing those animations into a project and controlling them in gameplay.

Vertex animation textures

The animation is in the texture.

OpenVAT records the evaluated mesh, frame by frame. A shader reads that motion back as vertex offsets, so the engine doesn’t need to reproduce the original rig, modifier stack, or simulation.

This folding example shows the same animation as texture data, vertex offsets, and the final mesh. It’s a useful way to see what the texture is actually doing.

The idea behind it

How vertex animation textures work

Each vertex gets a location in a texture, and time runs through the frames. The values stored there describe how the mesh moves. Playback happens on the GPU.

I walk through the format, the encoding, and the shader side in this video, with examples of what you can do with the result.

Blender-native

I built the baking around Blender’s evaluated geometry. If a modifier, Geometry Nodes setup, or rig deforms the mesh, OpenVAT can capture the result.

More than positions

Normals and custom per-vertex attributes can be encoded too. That gives a shader more to work with than a single position animation.

Playback you can change

The texture holds the data; a shader decides how to use it. Timing, per-instance offsets, masks, and blending can make the same bake useful in different ways.

The Unity side

From a bake to something you can use in a game

The Blender encoder is only half of OpenVAT. I also built a Unity receiver to bring the exported mesh and textures into a project, set up the material, and make the animation usable at runtime.

That means working with shaders and playback from gameplay code, not just watching an animation loop. It’s the side I use for characters and effects in VSPX.

My part in it

From Blender to the engine

I built both sides of the workflow: a Blender encoder driven by Geometry Nodes and Python, and a Unity receiver with import, shader, and playback tools. Building them together meant working through the practical details too: vertex mapping, normals, precision, and engine import settings.

Other engines

Beyond Unity, OpenVAT includes simpler shader examples for other engines, including Unreal and GLSL templates. AntzGames built a separate, more developed Godot integration for the community.

Integrations & setup →Community Godot project ↗

One constraint to know

The mesh needs stable topology: the vertex count and order must stay consistent through the animation. The motion itself is baked; playback and other runtime behavior depend on the engine integration and shader.
